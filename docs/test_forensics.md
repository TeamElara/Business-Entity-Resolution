## Findings (26 Sep)

1. **Test has ~24% more S2/S3 records per S1** (train 4.68, test India 5.82 / US 5.76 / France 5.53),
   while record quality is the same: blank addresses, non-Latin names, domain-like names, phone / ID /
   "doing business as" noise, address length and house-number formats all match train within ~1 point.
   Train has 3.46 true matches per S1, so test has **~2.3 orphans per S1** (train 1.22).
2. **Train orphans are lone, unique businesses**, not unmatched copies of an S1 business:

   | train | exact name in S1 | name + address numbers in S1 | pool twin (same name + numbers) |
   |---|---|---|---|
   | India matched | 21.2% | 13.4% | 21.9% |
   | India orphan | 4.5% | 0.07% | 0.2% |
   | US matched | 36.6% | 20.5% | 21.0% |
   | US orphan | 6.2% | 0.02% | 0.2% |

3. **Test orphans are the same kind, just more of them.** If test S1 had been subsampled (orphans =
   records whose S1 was dropped), test would show more pool twins without an S1; it shows fewer
   (India 11.8% → 9.5%, US 7.2% → 5.6%). Solving the exact-name share for the orphan fraction gives
   ~41% orphans in the India test pool vs 26% in train, consistent with 2.3 vs 1.22 per S1.
4. **Consequence:** validation (26% orphans) is easier than test (~40%). Every orphan that the matcher
   attaches to an S1 is a false positive, so precision drops on test. Validation that weights orphans
   (or S1 with orphan candidates) ~1.6x should predict the leaderboard better and is the natural
   "test-like weighting" for training and thresholds. Orphans rarely share an exact name with any S1
   (4–6%), so an orphan score from record-only features plus reverse-search competition is promising.
5. Smaller differences: test US S1 names are less often shared by 2+ S1 (29% vs 36%); France pools
   have more one-token (domain-like) names (7.6%) and almost no compound house numbers.

## Compute note

Everything here (forensics, reverse search, orphan model) runs on an 8 GB laptop: peak RAM ~3 GB,
reverse search ~1.7 h per split with 8 threads. If a step ever becomes a bottleneck, recommended specs
are 16 GB RAM and 8+ cores (or Kaggle CPU, 30 GB); the scripts take `--countries` and chunk sizes so
another teammate can run one country at a time.
